## Purpose and fixed boundaries

V3 retains the V1 processing rules and V1-style UI while putting all large-file
work in disposable Fargate workers. S3 is the sole durable application store;
DynamoDB, EFS, EKS and Lambda are intentionally not used.

- The small API authenticates, authorises, receives uploads, creates durable
  records and serves status. It never parses or transforms user data.
- One leased worker owns one session over initial profile, repeated key-impact
  analysis and final preparation. It does not start Glue.
- One asynchronous mutation dispatcher consumes SQS FIFO and is the sole
  authority to start Glue and write terminal mutation status.
- Glue job `s3-uploader-v3-ingest` creates/appends/restores S3 Tables/Iceberg,
  QC and audit history. Do not replace its script/job with V1 assets.
- Correct ordering is raw-key selection, sanitisation, type projection/staging,
  then Glue. Sanitised values must never be used as the deduplication basis.

secure and require a signing secret of at least 32 characters. The trusted
development identity panel sends only `X-Pilot-User-Id`; roles and grants are
resolved in the API and are never accepted from browser request data.

| Profile | Effective permissions |
| --- | --- |
| `local-admin` | All account-discoverable customer S3 Tables buckets/namespaces; create bucket/namespace, uploader table deletion, history, rollback and skill files. |
| `local-editor` | Configured bucket/namespace scope; history, rollback and skill files in that scope. |
| `local-unassigned` | Denied because it has no bucket assignment. |

Administrators discover all customer S3 Table buckets in the account, including
future buckets. Editors are deliberately application-scoped; update backend
profile mapping to grant a future bucket. Table deletion is administrator-only,
limited to uploader-managed tables, excludes `uploader_upload_history`, and
returns `409 TABLE_MUTATION_IN_PROGRESS` while a table lock exists.

Administrators can create table buckets and namespaces. IAM keeps broad access
to the minimum AWS-required `s3tables:CreateTableBucket` action only; discovery
and table operations are bucket/table scoped. Do not replace this with a broad
account-administrator policy.

## Deterministic leased-worker workflow

At first non-empty file selection the browser calls
`POST /api/v3/worker-leases`. The API, not the browser, calculates:

```text
routing score = sum(file size in bytes / format allowance)
score <= 1.0 -> BASE  (4 vCPU / 16 GiB)
score > 1.0  -> LARGE (8 vCPU / 32 GiB)
```

| Case-insensitive extension | BASE allowance |
| --- | ---: |
| `.parquet`, `.parquet.gzip` | 128 MiB |
| `.csv`, `.tsv` | 64 MiB |
| `.xls`, `.xlsx` | 32 MiB |

`.parquet.gzip` is matched before shorter suffixes. Browser MIME type is not
trusted. Unsupported extension, absent/invalid size, or zero size is rejected
before launch.

Selection changes conserve capacity:

1. Same deterministic size updates the idle lease manifest and reuses its task.
2. A base/large size change cancels the idle lease and launches exactly one
   replacement because Fargate cannot resize a running task.
3. Empty selection cancels an unattached lease.
4. A rejected/profile-only session may yield a compatible worker to a corrected
   selection. A live preparation or Glue session is never rebound.

An unattached lease expires after 10 minutes; an attached task can wait 30 idle
minutes for key selection or acknowledgement. Lease cancellation/expiry is
read from S3, with a heartbeat every 10 seconds. One task uses encrypted
ephemeral storage and runs profile, key analysis and preparation in child
processes, reusing its local immutable-source cache. It deletes cache on
completion, cancellation or expiry; cache loss is recoverable from S3 versions.

There is no automatic promotion. The base worker stops before Glue submission
and records `RESOURCE_LIMIT_EXCEEDED` when child RSS reaches 12 GiB, temporary
storage reaches 70%, `MemoryError`, Arrow/Polars allocation failure, or an
equivalent OOM condition occurs. Only then can the user choose **Retry using
large worker**. It restores durable earlier results and restarts only the
interrupted phase. It never retries a possibly-started Glue operation, and base
and large workers never run concurrently for that lease.

## Files, schema and healthcare sanitisation

Supported uploads: Parquet, Parquet GZIP, CSV, TSV, XLSX and XLS. Multiple
files are allowed only when their **normalised column-name sets** match. Order
does not matter. Normalisation lowercases and maps spaces, slashes,
parentheses and hyphens to collapsed underscores.

Different inferred source types are allowed. A new table stores a conflicting
column as `STRING` and documents that choice in review. An append projects to
the immutable table contract. Rejection is limited to missing/additional
normalised columns or later contract validation failure.

The first create fixes ordered target schema. Appends require an uploader
contract and at least 50% normalised source-to-target match per file. Extra
source columns are ignored; missing target fields become typed NULL. Tables
without an uploader contract are browse-only, not safe V3 append/history/
rollback targets.

Sanitisation is mandatory, worker-only and occurs before temporary staging.
The review response shows up to five short, non-empty examples for a
non-protected candidate column so a user can choose a key or optional manual
encryption field. Automatically protected fields (including detected NRIC
columns) are always masked: neither their values nor their quality counts are
returned. Review examples never enter staging manifests, QC reports, upload
history, or Glue arguments.

| Data class | Action |
| --- | --- |
| Names, DOB, phone/contact, home address/street/building fragments | Drop column |
| HRN/MRN, CSN, patient/case/account/subvention identifiers | AES-encrypt; STRING |
| Postal/ZIP | Retain two digits; STRING |
| AGE | Band; STRING |
| NRIC-shaped values in eligible string columns | AES-encrypt; STRING |
| Worker-reviewed manual candidates chosen by user | AES-encrypt; STRING |

NRIC detection samples at most five populated values and flags at least three
matching shapes; it is a heuristic, not checksum validation. Only `STRING`,
`BIGINT`, `DOUBLE`, `BOOLEAN`, `DATE`, and `TIMESTAMP` reach staging.
Timestamps are microsecond precision; time-only values become strings. A
temporal conversion that would discard populated data fails rather than
silently becoming NULL.

## Immutable de-duplication contract

The first user-acknowledged key is saved in the table contract and never
changes. Once configured, the UI hides the selector.

- A locked `A+B+C+D+F` table with incoming `C+D+F` derives active key `C+D+F`.
- If no locked column appears in the incoming source, append proceeds without
  deduplication and informs the user. The table key remains unchanged.
- A keyless table continues to show the selector. The first key requires raw
  impact analysis and an unexpired 30-minute acknowledgement token, then is
  saved prospectively.
- Existing rows are never rewritten. Cross-era records are not matched merely
  because a subset of identifiers happens to equal an older record.

V1 raw semantics apply to the current incoming batch: exact same-key/same-row
duplicates retain one; same-key/different-row conflicts drop every row in that
conflict group; raw-distinct values remain distinct after sanitisation. Impact
analysis returns incoming rows, unique keys, exact duplicates, conflict groups/
rows and expected retained/skipped rows without staging or Glue side effects.

## Preparation, SQS FIFO and Glue

The worker writes version-pinned, sanitised Glue-safe Parquet and a manifest
to S3. The manifest contains source versions, ordered schema, prepared files,
row/dedup metrics, sanitisation metadata and immutable context. Empty complete
submissions fail. A conflict can legitimately exclude one source in a multi-file
upload; failure occurs only if every file retains zero rows.

Create, append and rollback share one physical FIFO queue:
`s3-uploader-v3-mutations.fifo`. `MessageGroupId` is the SHA-256 of table
bucket ARN, namespace and table. SQS is still the durable queue; the dispatcher
is its custom consumer/scheduler.

```text
API -> S3 immutable command/status -> SQS FIFO -> one dispatcher -> Glue -> S3 Tables
                 ^                         |
                 |             leased worker writes READY_FOR_MUTATION
                 +-------------------------+
```

The one 0.5 vCPU/1 GiB dispatcher tracks at most 50 receipts and runs at most
five different-table Glue operations, matching Glue `MaxConcurrentRuns=5`. It
polls every 10 seconds, sets visibility to 120 seconds and renews receipts
every 30 seconds. It retains each receipt through preparation and terminal Glue
state, then writes terminal S3 state, releases its owned lock and deletes that
message—never earlier.

Thus A1, B1 and C1 can run concurrently, while A2 remains withheld until A1 is
terminal and acknowledged. Same-table work is queued, not rejected. Different
tables remain concurrent up to the Glue capacity limit. Glue starts with
`JobRunQueuingEnabled=true`; capacity errors return a message to
`READY_FOR_MUTATION` without losing it.

Immediately before Glue, the dispatcher conditionally owns:

```text
s3-uploader-v2/table-locks/<sha256(table_bucket_arn, namespace, table)>.json
```

The lock contains operational ownership only. It uses ETag matching for renew,
release and expired-lock takeover. Startup includes recovered locks in the
five-run count. The mutation DLQ allows five receives and has a CloudWatch
alarm. New Glue calls omit `--LOCK_*` and `--QUEUE_*`; Glue treats these only
as optional legacy arguments for pre-rollout work. This prevents the old
`GlueArgumentError ... --QUEUE_KEY` failure.

## History, rollback, cards and skills

Each Glue mutation writes an Iceberg audit record and a value-free JSON history
projection below:

```text
s3://ah-data-analytics/temp_s3_update/web_ingest/upload_history/<scope>/<table>/
```

History includes actor/time, files, reporting month, snapshots, rows before/
uploaded/after, duplicate/conflict metrics, sanitisation choices, timings,
status and failures. Table cards read Iceberg snapshot `total-records` without
a data scan and format dates in Singapore time.

Only the latest successful uploader-managed update with a previous snapshot can
be rolled back. Initial creation has no earlier snapshot. Rollback needs explicit
confirmation and is idempotent per owner/table/upload. It enters the same FIFO
group, restores the recorded snapshot, reloads Iceberg metadata directly,
verifies row count and writes QC/history. Never blindly retry a mismatch.

Skill management is current on the V1 routes: list/upload at
`/api/skills/files`, download at `/api/skills/files/download`, and confirmed
delete at `/api/skills/files` using `DELETE`. The old Method Not Allowed/Not
Found behavior is not part of the V3 contract.

## Durable state, retention and operations

| Purpose | S3 prefix |
| --- | --- |
| Raw immutable sources | `s3-uploader-v2/uploads/<session>/raw/` |
| Compatibility session | `s3-uploader-v2/compat-sessions/<session>/session.json` |
| Worker lease | `s3-uploader-v2/worker-leases/<lease>/lease.json` |
| Job request/status/events | `s3-uploader-v2/jobs/<job>/{request,status,events}` |
| Mutation command/request mapping | `s3-uploader-v2/mutations/` |
| Prepared Parquet/manifest | `s3-uploader-v2/jobs/<job>/prepared/` |
| QC | `s3-uploader-v2/qc/<job>.json` |
| Table contract | `ah-data-analytics/temp_s3_update/web_ingest/table_contracts/<scope>/<table>.json` |

Landing objects use SSE-KMS and versioning. Raw objects expire after one day;
prepared artifacts after 30 days. State uses S3 ETag conditional writes plus
`state_version`, preventing stale worker heartbeats from erasing a newer API
session binding, cancellation, retry or terminal state.

Lease states: `STARTING`, `AWAITING_UPLOAD`, `PROFILING`, `AWAITING_KEY`,
`ANALYSING_KEY`, `AWAITING_CONFIRMATION`, `PREPARING`, `COMPLETED`,
`RESOURCE_LIMIT_EXCEEDED`, `FAILED`, `EXPIRED`, `CANCELLED`.

Mutation states: `QUEUED`, `CLAIMED`, `PROFILING`, `PREPARING`,
`READY_FOR_MUTATION`, `STARTING_GLUE`, `RUNNING_GLUE`, `SUCCEEDED`, `FAILED`.

Investigate in order: S3 session/lease/job/mutation record; ECS stopped-task
reason and CloudWatch log; Glue run/log; QC/manifest; audit projection and
Iceberg snapshots. A stopped disposable worker is normal after completion,
cancellation or expiry. Never manually remove a lock before proving the owning
mutation and Glue run terminal.
